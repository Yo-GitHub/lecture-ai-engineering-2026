- **学習後に残った失敗と、その型：**

  2. 「オフィスアワーは事前予約が必要ですか」

  どちらも「根拠なしの質問に断定した」という失敗であり、学習後の形式の崩れはなかった。

- **知識を問う質問（セクション6）の結果（学習前の分類 → 学習後の分類）と気づいたこと：**

  - 「この講座の最終課題の締切はいつですか」：`format_error` → `asserted`
  - 「担当教員の名前は何ですか」：`format_error` → `needs_review`
  - 「次回の講義のテーマは何ですか」：`format_error` → `needs_review`

  今回の実験から、回答形式を学習させることと、回答の根拠を正しく判断させることは別の課題だと分かった。

## 宿題

- **取り組んだレベル：** 基礎

- **変えた設定やデータ：**

  `CONFIG` の `lora_r` を16から8に変更した。

  その他の設定や学習データは変更せず、Colabのセッションを再起動してから再学習と評価を実行した。

- **結果（比較表や数字）：**

  | 項目 | 変更前 | 変更後 |
  |---|---:|---:|
  | `lora_r` | 16 | 8 |
  | 学習時間 | 233秒 | 234秒 |
  | 学習ステップ数 | 40 | 40 |
  | エポック数 | 20 | 20 |
  | 最終Training Loss | 未記録 | 0.013214 |
  | 学習後 `format_rate` | 1.0（100%） | 1.0（100%） |
  | 学習後 `content_rate` | 0.9048（90.5%） | 0.9048（90.5%） |
  | 学習後 `both_rate` | 0.9048（90.5%） | 0.9048（90.5%） |
  | 退行した質問 | なし | なし |

  `lora_r` を16から8に半減させても、今回の21問の評価では正解率に変化がなかった。

  学習時間も233秒から234秒となり、短縮は確認できなかった。

  変更後のTraining Lossは、Step 10で1.561172、Step 20で0.082881、Step 30で0.016829、Step 40で0.013214となり、学習の進行に伴って低下した。

  変更前の最終Training Lossは記録していなかったため、Lossの直接比較はできなかった。

  今回の条件では、LoRAランクを小さくしても評価結果は維持された。ただし、評価問題が21問と少ないため、ほかのデータでも同じ結果になるとは限らない。

- **ファインチューニングが向く場面・向かない場面についての考察：**

  今回の実験では、LoRA学習によって指定されたJSON形式で回答する能力が大きく改善した。

  そのため、出力形式や回答の書き方など、一定のルールに沿った振る舞いを学習させたい場合には、ファインチューニングが有効だと考えた。

  一方で、FAQにない質問に対して誤った情報を断定する問題は残った。ファインチューニングによって回答形式が整っても、回答内容の正確性まで保証されるわけではない。

  また、提出期限や開催日時など、変更される可能性のある情報をモデルに覚えさせるだけでは、情報が更新された際に対応しにくいと考えられる。

  このような情報は、最新のFAQや資料を参照して回答する仕組みの方が適している場合がある。

  今回の学習を通じて、**回答形式を安定させるための学習と、回答に必要な知識を参照する仕組みは、目的に応じて使い分ける必要がある**と感じた。
